## 修复范围

- 提交、查询、交付使用独立有界通道，按到期时间公平调度；旧任务/慢请求不再永久占住队列。查询和交付失败使用退避。
- 素材映射保存有效期，在确认尚未发送的提交前重新检查；未知上传/未知付费请求不自动重试。
- 暂停/恢复查询保留正在执行的租约，新用户操作在并发写回时不会丢失；attention 停止自动轮询。
- 提示词结果收尾独立于被删除的原项目，单条异常隔离并退避，不会重调已有结果的模型。
- Core 加密保留工作输入，并按原版本恢复丢失或过期的网关临时副本，原请求与计费身份不变；恢复失败有明确终态或有界 attention。
- AI Work 限制上传、读取、DNS/TLS 和响应体资源，准备完成后重新确认容量及授权有效期；视频缓存清理保护所有在途文件租约。

[运维说明](../scripts/production-ops/README.md) 记录备份、告警、维护抑制、恢复密钥和原请求核对步骤。备份每天生成并保留七代，Windows/云服务器互存加密副本；监控检查长任务、收尾失败、待核账单、磁盘与备份时效。没有配置外部邮件/即时消息告警目的地。

原长时间空转的辅助已完成任务达到 8 次重试后被隔离，等待运维确认；它尚未完成，也没有自动重提视频。另一条已发送但结果未知的历史视频仍保留原预算查询，23 笔历史待核费用不能当作零费用或批量释放。解除 attention 必须先备份并证明原请求、Key、预算、版本及素材一致，检查没有已发送/未知视频步骤，再仅恢复同一请求的调度；不得创建新任务代替或删除已发生费用。

Windows 守护仍需要原用户已登录，DPAPI 凭据恢复依赖原 Windows 身份。当前系统盘空间偏低的告警保留，生产数据与构建主要位于 E 盘。上游排队、短期签名和迟到回执仍需持续观察；本次验证不能替代长期运行观察，也不承诺上游永不失败。
