# 视频来源连线与修改入口实施记录

用户要求尾帧续写在画布直接关联原视频，结果页增加修改入口。实施范围为现有续写、领域输入解析、结果操作与本地备份；QA48 初次实施没有调用真实生成接口。后续整体审计 QA50 按用户授权进行真实文字与视频流程验证，证据另行记录；上游原片修改能力仍未开放。

2026-10-05 用户明确纠正：关联必须在画布完整串联，不能只存来源字段或隐藏尾帧节点。本节替代 QA48 的直接尾帧输出设计。

续写显示“原生成草稿 → 固定视频结果 → 尾帧参考 → 续写草稿”，续写提示词单独连到草稿。生成来源以原 Run.nodeId 和 resultAssetId 核验；原生成节点不存在时只展示可核验的固定视频结果与后续关系。帧节点保存 sourceVideo（提取图片assetId、sourceAssetId、sourceRunId、timeSeconds）。原视频可复用或添加准确的固定结果引用。执行仍只发送普通 image 输入中的本地 PNG，不因来源关系上传原视频。

Edge 新增可选 relation（result / tail-frame / revision）。来源边有明确的“生成结果”“尾帧来源”“修改来源”标签和虚线，普通文字、图片、视频输入仍为实线。来源边不进入 inputBindings、输入预检、参考上限、文字模型上下文素材或执行依赖；来源边也不授予收费权限。来源端口支持键盘和鼠标接线，核验原任务和素材绑定，不能把任意视频冒充来源。

关联统一使用原 graph/命令/事务引擎，可删除、撤销、重做和保存。删来源线即解除当前画布关联，来源标签和“查看原版本”同步消失；历史来源字段保留为审计证据。generationLinked / lineageRecorded / sourceVideo 区分已建立过关系的新节点，显式补齐操作不会重新接回用户主动删除的现代来源线；可通过来源端口手动恢复。

“补齐来源连线”只在用户点击时执行本地可撤销命令。旧尾帧 PNG 从本地缓存重新计算 SHA-256，与同项目成功视频本地提取的 PNG 逐一核对，只有唯一匹配才补线；缓存缺失、损坏、来源不唯一时明确报告并保留原数据。旧修改分支须有准确的 revisionSource/run/resultAsset 证据。旧 QA48 直接尾帧边显式转换成原视频→帧→续写链。保存时重新核对 Run/Asset 快照和项目修订，不猜测时间顺序，不调用网络。

结果页“修改并重新生成”读取所选Run.inputSnapshot，保留原规格、参考ID、顺序和别名，建立独立文字节点和视频草稿，并添加“原视频 → 修改草稿”的真实来源边。revisionSource记录原projectId/runId/assetId。打开/取消不保存作品；确认保存本地草稿，进入画布后单独确认新视频调用。原Run、素材、body、幂等键和账务不覆写。失败事务回滚，归档项目禁用。此功能是重新生成新版本，尚未开放原片局部修补或Core作业改版。

项目包导入补齐sourceAssetId的身份重映射，防止恢复后尾帧来源指向旧素材。新字段可选，原数据不覆盖；旧客户端遇到新增字段应更新后打开，不使用旧页面写回新草稿。

QA50：来源边在批量计划中也不作为执行依赖。应用润色保留修改来源，重新选择结果清除旧来源线，复制草稿不得把原结果归属于复制后的生成节点。导入只读历史可证明生成来源，不能变成可执行 Run；导入前校验来源线与原 Run、素材的对应关系。新提示词与原参考节点避让，普通提示词入口恢复已保存草稿，只有直接 AI 润色入口创建新的优化输入并按视频参数优先处理规格。

真实修改流程补充：原输入快照的 nodeId 仍指向同一 asset/result 身份时，新修改草稿直接连接原参考节点，保留原视频→尾帧关系；节点已被删或改成其他素材时，才创建独立的原参考节点，不猜测别的来源节点，不恢复被主动删除的来源线。全局默认时长和比例都未设定时，视频状态摘要使用当前授权实际成功的精确规格；不扩大为其他参数或其他 Key 的成功证明。
