# AI WORK Studio 升级、备份与回滚操作单

范围仅为 Studio 本地创作数据；不读取或迁移 Core 财务数据库。当前是离线待验收版，未批准实际部署、生产迁移或真实收费联调。

| 契约 | 当前支持 | 处理 |
| --- | --- | --- |
| 项目/项目包 schema 1 | 可读取、校验后事务写入 | 写权、修订与收费确认仍分别检查 |
| 项目/项目包 schema >1 的安全整数 | 保留，只读限制 | 不按旧结构转换，不覆写；新版包保留原文件 |
| 0、负数、小数、非有限数、非安全整数 | 不支持 | 拒绝写入，不自动修复 |
| Studio IndexedDB 结构版本 2 | 当前客户端可打开 | 与项目 schema 独立 |
| IndexedDB 结构版本 >2 | 当前客户端拒绝打开 | 使用兼容客户端；不得删库或降级恢复 |

`src/infrastructure/storage/release-compatibility.ts` 提供项目 schema 判定；纯判定在领域层共享，不引入数据库或网络依赖。新版原生项目当前只显示保留提示，不声称能够完整预览/安全导出未知结构。未知 Run/PromptRun 仍留在原库；未知格式可能阻止旧版展示或导出，应使用兼容版本处理，不能删日志解除限制。

升级前：

1. 停止新提交；已发出的任务继续按原服务、授权绑定、taskId 查询。停止轮询不等于取消或退款。
2. 记录客户端提交、浏览器配置文件以及完整 origin（协议/主机/端口）。同一浏览器同一 origin 才共享 IndexedDB；更换端口会形成另一个存储空间。
3. 在旧版仍可识别数据时明确导出完整项目 ZIP，并在隔离测试 origin/浏览器配置文件中检查导入与素材恢复。仅结构包不含媒体；“触发下载”不是已验证备份。
4. 另外保留原浏览器数据现场与原项目包。项目包仅为创作恢复，不是费用日志全量快照：执行请求体、幂等键、批准和会话 Key 不迁移，PromptRun 完整原日志仍依赖原库保留。
5. 不清空数据、不覆盖旧项目；新构建先在隔离配置中验证。生产版本切换需另行批准。

故障回滚：

1. 停新收费提交，保留已发出/结果未知的原身份与冻结 body；禁止换新键、素材 ID 或自动重试。查询、下载使用原身份；下载失败只重试下载。
2. 仅将前端资源换成兼容当前持久数据的版本，继续使用**同一 origin、同一浏览器配置、同一持久库**。若旧客户端不支持新的项目/库版本，保持拒绝写入，恢复兼容客户端。
3. **不能用较旧备份覆盖原库**。备份之后增加的 Run/PromptRun、费用证据、服务归属必须保留。创作恢复另存为新项目，导入历史只读，不能恢复运行权限或自动提交。
4. 对坏包或新版包，保留原文件与错误，不篡改 schemaVersion，不丢弃未知字段以换取通过。
5. 核对原任务、费用状态和素材后再决定是否恢复新提交；真实对账未核验时明确写未知。回滚不访问、不改写 Core 账本。

本机发行包需要 Node 22.18+ 的 22.x；默认固定本机端口 4188。升级测试使用独立 origin，实际迁移需注意与此前开发端口 4178 的数据隔离。独立验收、前端标识许可、Nginx 部署验证、真实 Core 能力及费用验证仍是正式发布前提。
