# T49 本地迁移与回滚演练

2026-10-02，单实施者自检，未进行独立审查或生产迁移。

在真实 Chromium IndexedDB 上运行 6 项检查：旧 schema 1 写入无法覆写已保存 schema 2；结构版本 3 拒绝旧客户端打开；未知 Run 与 PromptRun 原记录保持一致；升级前完整包可另存恢复创作和媒体，而备份后新增的费用证据在原库保持不变；损坏/新版包原 Blob 和字节保留；页面刷新不重提任务。所有例子均为本地假数据，0 真实 Core 请求。

首次目标回归 4 通过、2 失败：版本判定未拒绝无效数字，新版项目只有笼统读取失败。修正后 6 通过、0 失败、0 跳过。新版项目显示明确保留提示，编辑入口不开放。实际截图 `screenshots/T49-newer-schema-preserved.png` 已由实施者查看。

全量单元回归另发现两项前序集成问题：T48 同名 .ts/.mjs 守卫模块导致隐式解析错误；T47 Nginx 模板改动遗漏关闭原请求头转发。安全测试改为明确调用当前严格守卫，原拒绝断言保留；恢复 `proxy_pass_request_headers off` 并显式转发正文类型。固定无效目标占位名称与已批准模板一致，方法映射只读取本段 map。修正后 386 项单元通过。未运行 nginx -t，模板不能据此称为生产验证通过。

限制：没有操作真实 Core 账本，因此“不改账本”的证据是无相关数据库访问及网络副作用，不是生产账务审计。没有执行实际前端生产切换；演练核验的是同一原生持久数据上的旧写入拒绝、重新打开与另存恢复。未知原生 Run/PromptRun 不向旧格式归一化；兼容版本未提供时只能保留，不能保证旧版完整显示或导出它们。完整历史依赖保留原库，不把便携创作包当作账务快照。
