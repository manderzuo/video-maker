# 肖像图生视频研究：输入准入与动作提示词

核查日期：2026-10-05。依据当前真实测试、公开官方文档、原作者 GitHub 仓库。未将用户照片或 Key 传给新的第三方网站，没有重复付费试词。以下方案未在当前网关验证成功。

## 结论与可用路径

QA56 返回输入图片可能含真人，属于素材准入。没有查到能在当前通道可靠保证通过的提示词。写“已授权”“虚拟角色”不会创建服务器认可的授权资产；修改文案也不能保证照片被认可。应先确定人物素材的受支持身份和来源，再写动作。

| 目标 | 公开可用方案 | 当前项目的边界 |
| --- | --- | --- |
| 使用真实人物身份生成 | 官方真人肖像认证、授权、素材入库，使用资产 ID | 当前普通图片上传不能代替该流程；Core 能否接入待核验 |
| 使用虚拟人物反复创作 | 官方预置虚拟人像；符合信任规则的同账号原始模型产物 | 当前 Core alias seedance 的实际版本、账号及信任传递待核验 |
| 一张照片做眨眼、微笑、转头 | 本地 LivePortrait；有 ComfyUI 节点实现 | 独立动画工具，需要部署、硬件与依赖许可证核验；本轮没有安装 |
| 让参考人物模仿全身动作 | Wan2.2-Animate 的人物图片＋动作驱动视频 | 不只是提示词，需要动作素材和预处理；不保证半身照片补全全身效果 |

[火山方舟肖像指南](https://docs.volcengine.com/docs/ark/seedance-portrait-asset-guide?lang=zh)说明 Seedance 2.0／2.5 的直接真人脸输入限制，并提供授权素材、虚拟人像与可信生成产物路线。可信产物限同平台、同账号、近30天原始产物，包含符合生效日期的 Seedance 视频／尾帧及 Seedream 5.0 lite/pro 文生图。不能把任意外部 AI 图片、编辑重画、压缩转存后的图当作自动受信任素材；输入准入通过也不保证输出通过审核。

[真人资产录入文档](https://docs.volcengine.com/docs/ark/upload-real-person-portrait-assets?lang=zh)的流程是认证账号发起邀约，授权人登录并完成真人认证、上传本人素材，创作者接收有效资产，再通过 asset:// 资产 URI 使用。普通 Studio 素材 ID 与这种授权资产不同。当前公开材料不足以确认照片中儿童形象适用的具体录入条件，也不能仅凭照片文件名断言它是真人或虚拟人。

## 提示词怎么写

以下是素材已经通过受支持准入后的动作模板，不是保证过审的文字补丁：

> 以图片1中的人物为主体，保持人物外貌、发型、服装和室内背景一致。固定镜头，人物自然眨眼一次，露出轻微笑容，头部缓慢向侧面转动少许后回到正面；肩部保持稳定，动作连续、幅度小，光线自然。不新增人物，无对白、字幕或水印。

画面比例、时长和清晰度继续以生成设置为准，不在正文写相冲突的规格。参考编号应对应实际提交顺序。

若目标是“让原照片动起来”，应核验首帧模式参数。官方[提示词指南](https://docs.volcengine.com/docs/ark/seedance-2-5-prompt-guide?lang=en)优先使用 first_frame／last_frame 角色；reference_image 配合“图片1为首帧”只是近似参考，并不严格匹配。当前网关尚未核验首帧角色透传，不能只加一句话就宣称实现，也不能照搬2.5参数到未知版本 alias。

## GitHub 方案核查

[LivePortrait 官方实现](https://github.com/KlingAIResearch/LivePortrait)已有推理代码、模型、Windows运行入口与交互界面，通过驱动视频／图像或姿态表情控制使肖像动起来，适合本次轻微面部动作。它不是仅凭一句话生成任意全身活动的引擎。[官方许可证](https://github.com/KlingAIResearch/LivePortrait/blob/main/LICENSE)为 MIT，同时明确 InsightFace 预训练检测模型限非商业研究；不能把整体依赖视为无条件商用。

[ComfyUI-LivePortraitKJ](https://github.com/kijai/ComfyUI-LivePortraitKJ)提供节点、图生视频和视频驱动示例，支持 MediaPipe 等替代检测器。作者说明 MediaPipe 路线改善许可条件；正式集成仍须固定提交并核对实际下载模型和依赖，不能把 README 声明当作本项目许可验收。

[Wan2.2 官方仓库](https://github.com/Wan-Video/Wan2.2)的 Animate 模式输入人物图像与动作视频，配套姿态／人脸预处理及推理实现。更适合保持人物形象并模仿全身运动；当前机器显存、速度与输入适配没有测试。

[byteplus-seedance-mcp](https://github.com/skeetmtp/byteplus-seedance-mcp)是 API 封装参考，也明确真人脸输入受限，未提供通用提示词解除限制的实现。它不是已验证适配 api.gemstory.cn 的成熟替换件。

部分社区教程宣称第三方通道可直接上传真人脸；这类宣传不足以证明授权来源、稳定性或当前网关支持。本轮不据此推荐把照片与 Key 交给陌生供应商。

## 对当前产品的建议

先修复明确失败原因的展示，再核验 Core 实际上游版本、授权素材 URI 与首帧角色契约。若支持，在既有 Core 授权边界下组织素材和参数；不由 Studio 持有上游管理 AK/SK、不另造账户或账务。只在授权资产可用后做一次最小真实验证。LivePortrait／Wan 属于可选新能力，需要单独收口，不能暗中替换已批准执行路径。
